# 滑一下 0.5.2 测试执行说明

编制日期：2026-10-26。适用版本：versionName 0.5.2 / versionCode 21。

本说明配合 [268 条详细用例](test-cases-0.5.2.md) 和 [CSV 执行记录表](test-cases-0.5.2.csv) 使用。这里给出准备方法、数据、执行顺序与验收口径。它不是已执行的测试报告。

## 1. 优先级与执行顺序

| 阶段 | 范围 | 退出条件 |
|---|---|---|
| 1：构建与安装 | APK 身份、签名、首启、旧版本覆盖、构建 | 可以稳定安装、启动、升级；配置和隐私迁移正确 |
| 2：冒烟 | 下方 30 条快速集合 | 任一误滑、提前上滑、无限重试、泄露或崩溃即停止发布候选验收 |
| 3：核心回归 | 所有 P0，再执行 P1 | 核心规则、窗口、状态机、学习和恢复都具备证据 |
| 4：真机兼容 | 设备矩阵中的核心组合；每类真实广告单独统计 | 形成支持范围及已知限制，不用模拟器代替真机结论 |
| 5：专项 | 压力、耗电、长时间运行、备份、低存储、读屏 | 量化结果可比较；重大问题有明确处理结论 |
| 6：发布复核 | 缺陷回归、端到端、同一 APK 冒烟 | 阻断项全部关闭；未完成项和接受的限制已记录 |

建议冒烟 30 条：

`INS-001`、`INS-003`、`STA-001`、`STA-002`、`STA-006`、`STA-008`、`APP-001`、`APP-012`、`TXT-001`、`TXT-003`、`TXT-010`、`SCN-002`、`SCN-008`、`CYC-001`、`CYC-004`、`CYC-005`、`CYC-010`、`CYC-015`、`WIN-001`、`WIN-002`、`WIN-004`、`GST-007`、`LRN-006`、`LRN-007`、`LRN-016`、`DIA-015`、`PRI-001`、`PRI-002`、`E2E-001`、`E2E-006`。

其中节点异常、精确时钟、回调竞争等用例需要测试桩，不能仅靠手动点击证明通过。没有桩时先执行可操作项，其余标“阻塞”，不能把 30 条整体标为通过。

## 2. 测试环境与独立性

每次执行至少填写：APK SHA-256、版本、签名类型、测试日期、设备型号、Android/API、ROM 版本、目标应用名称/包名/版本、横竖屏、文字/学习方案、字体大小、诊断开关、自动上滑/观察开关、服务授权/连接状态。

使用独立测试设备或可丢弃模拟器副本做卸载、清数据、损坏存储、低空间和备份恢复测试。普通功能用例从明确的初始配置开始；验证持久化和升级的用例按其要求保留数据。一次用例的失败不能污染后面用例的前置条件。

### 基础配置 E0

| 项目 | 值 |
|---|---|
| 自动上滑 | 开启 |
| 观察模式 | 关闭 |
| 开发诊断 | 关闭；需要详细诊断的用例另行开启 |
| 发现新应用 | 开启 |
| 目标列表锁定 | 关闭 |
| 当前识别方案 | 默认方案 |
| 目标应用 | 只加入测试应用 A |
| 前台 | A 独占活动和焦点，无弹窗、键盘、通知栏和路径遮挡 |
| 起始动作状态 | 新服务或上个动作已超过冷却，且没有待确认/验证/重试/学习任务 |

“A/B”是测试角色：A 为目标，B 为非目标。需要两目标时必须明确把 B 加入。系统设置仅在明确加入目标的测试中才是目标，不应默认允许自动操作系统页面。

## 3. 执行方式与所需测试能力

| 方式 | 能验证什么 | 不能替代什么 |
|---|---|---|
| 本地 JVM 单元测试 | PromptDetector、PromptCycle、PatternMatcher、WindowSafety、GestureOutcome 等确定性规则 | Android 服务生命周期、真实节点、实际手势、存储和厂商行为 |
| Android 集成测试/可控页面 | 节点可见性、完整性、窗口、SharedPreferences、文件导出和生命周期 | 真实广告供应商布局、厂商回收、真实耗电 |
| 手工测试 | 首次配置、列表、输入、管理流程、文案和恢复路径 | 精确到 1ms 的边界、受控回调和高频竞争 |
| 真机专项 | 实际播放器切换、系统弹窗、后台存活、机型与 ROM 兼容 | 穷举所有时序和所有广告布局 |
| 性能测量 | CPU、PSS/Java 堆、帧耗时、写盘、唤醒、耗电趋势 | 仅凭主观“流畅”或一次电量读数下结论 |

本次交付包含用例与执行表，**没有新增可运行测试桩、测试 APK 或仪器测试框架**。以下能力需要开发准备或扩展现有测试设施：

1. 可控目标 A：在同一个窗口切换正常、广告初期、就绪状态，独立控制 text、contentDescription、可见性和控件结构。
2. 异常节点读取桩：控制 root.refresh、getChild、节点数量、文字长度以及 deepRefresh 失败。
3. 单调测试时钟与可推进调度器：精确覆盖 300ms、2s、15s、超时及待执行回调。
4. 手势网关桩：记录所有提交，控制接受/拒绝、完成/取消、回调延迟与旧回调。
5. 窗口快照桩：独立控制活动、焦点、包名、ID、层级、边界和遮挡。
6. 存储与文件故障桩：注入损坏 JSON、旧字段、写入失败、导出失败及待写任务竞争。

测试无障碍服务时，要确认 UI 自动化工具没有抑制被测无障碍服务。部分 UiAutomation/UIAutomator 连接会改变服务连接或窗口状态；如使用仪器测试，可按平台能力配置不抑制服务。无法控制时，使用 `adb screencap`、外部录像及不含页面正文的手势计数采证，勿把工具导致的断连直接判成产品缺陷。

### 有效学习样本基线

用纯规则样本先建立可用正例。特征名为便于测试的符号，并非可直接导入真实设备的控件特征。

```text
package = app.a
aspect = 0.5
complete = true
共同特征 = root, player, navigation, anchor=player
正常 = 共同特征 + feed + like
广告初期 = 共同特征 + advertiser + disabled
就绪 = 共同特征 + advertiser + enabled + swipe_control
```

测试某一校验边界时，只改变对应条件，其余条件必须继续满足。例如验证“90%”时必须保留 againstNormal/againstAd 全部关键特征；验证“恰好 6 个特征”时仍需公共结构至少 3 个、相对正常至少 2 个新特征以及相对初期至少 1 个差异。

| 维度 | 最低建议覆盖 |

| ROM | 可获得的 Pixel/原生、三星、小米、OPPO/一加、vivo；华为 Android APK 兼容环境单列 |
| 屏幕 | 小屏约 320dp 宽、常规手机、大屏、平板或折叠屏；横竖屏 |
| 导航/显示 | 手势与三键；字体默认、1.5倍、最大；显示尺寸默认与最大 |
| 窗口 | 全屏、分屏、浮窗、通知栏、系统弹窗、键盘、来电 |
| 目标 | 红果短剧、红果漫剧、可控测试 A；各自记录应用版本 |
| 内容 | 普通视频、倒计时、直接就绪、同提示连续广告、不同广告供应商与布局、不可读画布 |
| 识别 | 默认、自定义、竖屏学习、横屏学习、缺少适用样本 |

不要强行全笛卡尔积。对所有高风险场景至少做核心组合覆盖；配置和布局用两两组合覆盖，并对出现过缺陷的组合保留专项回归。厂商后台与手势相关 P0 必须有真机证据。

## 6. 观察与取证方法

每一次自动动作至少记录：动作序号、测试用例 ID、t0/提交时间、动作前的前台包名和窗口 ID/边界、当时配置、可读完整性、确认与取消结果、手势接受值、完成或取消回调、两次结果验证、重试资格与最终是否真正切换播放内容。

对误滑、提前滑和重复滑，优先保留连续录像与事件时间线。只看到首页“最近上滑”不足以证明广告已切换；系统手势完成也不能证明业务成功。隐私用例中不要通过开启完整诊断来证明“诊断关闭不保存文字”，避免测试自身改变条件。

当前采样与事件驱动存在轮询和系统 IPC 延迟。人工测试记录实际延迟范围；只有受控单元/集成调度环境才用于 1ms 边界断言。极短切窗竞争是系统坐标分发的实测风险，不把一次未复现表述成理论上的零竞态保证。

## 7. 建议性能门槛与统计口径

以下为**建议验收线，尚非产品承诺或本次实测结果**；首次测量后结合最低配置设备确定正式预算。

- 冷启动到首页可操作 P95 ≤ 3 秒，至少 10 次，记录冷/热启动条件。
- 普通点击、切页出现反馈 P95 ≤ 300ms；较慢的系统授权/文件选择不计入应用普通操作。
- 8 小时稳定性零崩溃、零 ANR、零非目标误滑、零同提示失控循环。
- 内存对照在相同页面和内容下预热，比较多个时间点及 GC 后趋势；不得持续随轮数增长。不要直接把一次 PSS 差异当泄漏。
- 耗电至少做关闭服务、服务开但非目标、目标扫描、诊断开四组；固定亮度、网络、播放内容与时长。优先使用 Battery Historian/系统电池统计等数据，不仅记录电量百分比。
- 记录高频事件下实际扫描次数、主线程耗时、写盘频率；同一提示不应因事件数量增加而增加动作次数。
- 正常可控页面保持就绪后应在一次轮询加确认的量级内开始处理；不要对真实第三方页面承诺固定端到端时延。

## 8. 风险项与范围边界

以下用例需要明确结果，而不是在报告中默认通过：

- `TXT-015`：61/99/100 秒等异常倒计时可能暴露范围回退、正则后缀匹配风险。
- `TXT-016`：教程、引用、否定文本含就绪词，当前规则并无完整语义理解能力。
- `CYC-020`：15 秒间隔当前保证在同一服务实例内；进程重建后是否需要延续是待确认产品要求。
- `MGR-013`：无效或丢失的当前方案可能触发默认回退，需检查是否意外扩大有效目标范围。
- `LRN-020`：大字体和方向变化后控制条仍须能滚动访问取消；换方向的样本不能混录。
- 始终保留同一提示且无新倒计时的连续广告，可能需要手动操作，属于当前保守策略边界。
- 当前使用全局单方案，绑定 A 的学习方案不会自动为 B 选择另一个方案。
- 当前无 OCR；纯视频画布提示不可读不等于检测器应当识别成功。
- 独立就绪节点可以优先于另一个残留倒计时节点，这是当前明确规则；务必用真实广告核对独立就绪确为可操作提示。
- 系统/厂商是否自动恢复无障碍服务、是否允许后台存活，应记录实际差异，不能假定应用可绕过系统。

如验收目标未满足，应开缺陷或先确认产品要求；不能为了使报告通过而把预期改成当前错误行为。

## 10. 现有自动化入口

```powershell
# JAVA_HOME 指向 JDK 17 或 21，Android SDK 路径已配置
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

规则测试位于 `app/src/test/java/com/example/autoswipeassistant/`。可按测试类筛选，例如：

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests "com.example.autoswipeassistant.PromptCycleTest"
```

现有测试类与关联规则：

| 测试类 | 主要关联模块 | 覆盖边界 |
|---|---|---|
| AppReadinessTest | STA | 准备状态计算，不代表真实系统授权/连接已验证 |
| CandidateHistoryTest | APP | 最近访问排序，不覆盖 Android 列表交互 |
| PromptDetectorTest | TXT | 文本规则与分节点优先级，不覆盖所有真实广告 |
| CustomPromptTest | CUS | 自定义匹配与归一化，不覆盖编辑器保存/旋转 |

| GestureOutcomeTest | GST | 结果分类和稳定性，不证明实际播放器切换 |
| WindowSafetyTest | WIN | 纯窗口快照判断与路径，不证明真实切窗零竞态 |
| PatternMatcherTest | PAT、MGR | 控件样本匹配与方向合并，不覆盖学习浮层与磁盘持久化 |
